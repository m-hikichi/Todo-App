# プロジェクト要件定義

## プロダクトゴール
単一のコードベースで、次の2つの提供形態に対応するTodoアプリを構築する。
1. Dockerコンテナモード（ローカル実行およびサーバー配置向け、ブラウザUIで操作）
2. デスクトップアプリモード（Windows/macOSへインストールし、アプリケーションウィンドウで操作）

Docker利用時はブラウザUI、デスクトップアプリ利用時は専用ウィンドウUIを提供する。

## 対象ユーザー
- 軽量な個人タスク管理を求める個人ユーザー
- ローカルマシンや社内サーバーで運用する小規模チーム
- ブラウザを常時開かずにデスクトップアプリとして利用したいユーザー

## MVPスコープ

この文書は「何を満たすべきか（WHAT）」を定義する。  
実現方法（HOW）と実装仕様は`docs/specs/`配下のSPEC文書で定義する。

### 機能要件

#### 要件IDポリシー
- 要件IDは`FC-LL-MM-NNN`形式で管理し、トレーサビリティ維持のため固定する（構造改訂時のみ再採番を許容）。
- `FC`は大分類/中分類/小分類を表す階層IDとして運用する。
- `LL`は大分類を表す2桁コード（例: `01`=基本操作、`04`=実行・配布・運用）。
- `MM`は大分類配下の中分類を表す2桁コード（例: `01`=CRUD、`02`=一覧/フィルタ）。
- `NNN`は`LL-MM`配下での要件連番を表す3桁コード（`001`から採番）。

| LL | 大分類 |
|----|--------|
| 01 | 基本CRUD・一覧・状態管理 |
| 02 | 属性管理（開始予定日/締め切り/担当者/プロジェクト） |
| 03 | 親子タスク管理 |
| 04 | 実行・配布・運用 |
| 05 | クライアントUI挙動・通知 |
| 06 | タスク自動化 |

#### グループA: 基本CRUDと入力制約
| 要件ID | 要件 |
|--------|------|
| FC-01-01-001 | タイトル必須（1〜120文字）・説明任意でTodoを作成できる |
| FC-01-01-002 | 既存Todoを編集できる |
| FC-01-01-003 | Todoを削除できる |

#### グループB: 一覧・状態管理
| 要件ID | 要件 |
|--------|------|
| FC-01-02-001 | Todo全体を作成順（新しいものを先頭）で表示できる |
| FC-01-02-002 | 今日着手すべきTodoを表示できる（未完了かつ開始予定日時が到来したもの。`start_date`未設定Todoは即着手可能として表示） |
| FC-01-02-003 | 期限切れの未完了Todoを表示できる（`due_date`がJST現在日時より前で、`completed`以外のもの） |
| FC-01-02-004 | 完了Todoを表示できる |
| FC-01-03-001 | Todo状態を`active`（未着手）/`in_progress`（進行中）/`waiting`（待ち）/`completed`（完了）に変更できる |
| FC-01-03-002 | 状態（all, active, in_progress, waiting, completed）で絞り込める |

#### グループC: 属性管理（開始予定日・締め切り・担当者・プロジェクト）
| 要件ID | 要件 |
|--------|------|
| FC-02-01-002 | Todoに開始予定日時（start_date）を日本時刻（JST, UTC+09:00）で設定・更新・解除できる |
| FC-02-01-001 | Todoに締め切り日時（due_date）を日本時刻（JST, UTC+09:00）で設定・更新・解除できる。start_dateが設定されている場合、due_dateはstart_date以降のみ許可する |
| FC-02-02-001 | Todoに担当者を1名紐づけられる（未設定も許容） |
| FC-02-03-001 | 事前作成したプロジェクトからTodoへ0または1件のプロジェクトを紐づけられる。未設定のままでも保存できる |
| FC-02-03-002 | Todo作成フォーム近傍のプロジェクトUIから、プロジェクトをその場で作成・編集・削除し、以後のTodo入力で再利用できる |

#### グループD: 親子タスク管理
| 要件ID | 要件 |
|--------|------|
| FC-03-01-001 | Todo同士に親子関係を設定できる（親は1件、子は複数） |
| FC-03-01-002 | 親子関係で自己参照および循環参照を防止する。親Todo削除時は子Todoの親参照を解除（`parent_todo_id=null`）する |

#### グループE: 実行・配布・運用
| 要件ID | 要件 |
|--------|------|
| FC-04-01-001 | Dockerモード/デスクトップアプリモードのいずれでもsqliteストレージへ永続化する |
| FC-04-02-001 | Dockerモードでは同一バックエンドプロセスからブラウザUIを配信する |
| FC-04-03-001 | 運用監視およびDockerプローブ向けのヘルスチェックエンドポイントを提供する |
| FC-04-04-001 | ホスト/ポート/データパスを環境変数とフラグで設定できる |
| FC-04-02-002 | デスクトップアプリモードではブラウザを使わず、アプリケーションウィンドウでTodo操作できる |
| FC-04-05-001 | Windows向けにインストール可能な配布形式（例: installer + exe）を提供する |
| FC-04-05-002 | macOS向けにインストール可能な配布形式（例: .app + .dmg）を提供する |
| FC-04-06-001 | DockerモードとデスクトップアプリモードでTodoの中核挙動を一致させる |
| FC-04-07-001 | Todoデータをバックアップとしてエクスポート/インポートできる |

#### グループF: クライアントUI挙動
| 要件ID | 要件 |
|--------|------|
| FC-05-01-001 | UIは操作結果をページ全体の再読み込みなしで反映する |
| FC-05-02-001 | 開始予定日/締め切りに基づく通知をアプリ内で受け取れる。通知タイミングはユーザーが設定できる |

#### グループG: タスク自動化
| 要件ID | 要件 |
|--------|------|
| FC-06-01-001 | 繰り返しタスク（毎日/毎週/毎月）を設定できる |

### 非機能要件
- NF-001: 標準的な開発マシンで3秒以内に起動する
- NF-002: Todo件数1000件まで、通常API応答が500ms以内である
- NF-003: ローカル実行時に`docker run` 1コマンドで起動できる
- NF-004: Windows/macOSデスクトップアプリが外部ランタイムの手動インストールなしで起動できる
- NF-005: 基本的な入力バリデーションと安全なSQLパラメータバインドを行う
- NF-006: デスクトップアプリ初回表示までの時間を3秒以内とする
- NF-007: CIでホストにGo/Nodeを前提とせず、Dockerベースでビルド・テスト・ヘルスチェックを自動検証できる

## MVP対象外
- ユーザーアカウント管理と認証
- 複数ユーザーでのリアルタイム共同編集
- クラウド同期
- Linux向け配布パッケージ
- 並び替え機能（作成日/開始予定日/締め切り/更新日）
- インポート安全機能（dry-run、merge/replace選択、事前検証プレビュー）

## 仕様分割案
- SPEC-001: Todo中核ドメイン、API、UI挙動（ブラウザUI/デスクトップUI）
- SPEC-002: Docker実行とWindows/macOSインストール配布の実行要件およびパッケージング

## 受け入れ基準（MVP）
- AC-001: DockerモードでブラウザからTodoのCRUDと状態変更（active/in_progress/waiting/completed）ができる
- AC-002: Dockerモード/デスクトップアプリモードのいずれでも、アプリ再起動後にデータが保持される
- AC-003: `docker run`でアプリが起動し、ブラウザでUIを開ける
- AC-004: Windowsインストール版を起動するとアプリケーションウィンドウでUIが開く
- AC-005: macOSインストール版を起動するとアプリケーションウィンドウでUIが開く
- AC-006: Dockerモードとデスクトップアプリモードで中核挙動が一致する
- AC-007: Todoに開始予定日と締め切り（日本時刻/JST）、担当者、事前作成したプロジェクトを設定して保存できる。プロジェクト未設定でも保存でき、start_date設定時はdue_dateにstart_date以降のみ入力できる
- AC-008: Todoの親子関係を設定し、親タスク配下の子タスクとして表示できる。親タスク削除時は子タスクの親参照が解除される
- AC-009: UI操作時にページ全体の再読み込みなしで画面へ反映される
- AC-010: JST基準で、未着手/進行中/保留のうち開始予定日時が到来したTodoを表示できる。完了Todoは一覧に表示しない。`start_date`未設定Todoは即着手可能として表示する
- AC-011: 開始予定日/締め切りの到達前にアプリ内通知を受け取れる。通知タイミングはユーザー設定が反映される
- AC-012: 繰り返しタスク設定に従って次回タスクを生成できる
- AC-013: Todoデータのエクスポートとインポートでバックアップ/復元できる
- AC-014: Todo作成・編集フォーム近傍のプロジェクトUIからプロジェクトを作成・編集・削除でき、作成直後に選択候補と一覧表示へ即時反映される
- AC-015: UIから「今日 / 期限切れ / 完了 / すべて」のタブを切り替えて確認できる
